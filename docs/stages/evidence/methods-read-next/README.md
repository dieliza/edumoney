# Métodos de ingreso personalizados y lectura al continuar

25 de noviembre de 2026. Preparado, SIN publicar. Base pública comprobada: versión 105.

En el formulario de ingreso se añadió «+ Crear método de pago», un campo de nombre y «Crear y seleccionar método». El método se selecciona inmediatamente y queda disponible en el mismo espacio del usuario, tanto personal como comercial. Se conservan los métodos preestablecidos. Crear un método no crea una transacción. Se validan nombres, se evitan duplicados por mayúsculas/espacios, se muestra el error junto al campo y se conserva un método elegido explícitamente aunque la descripción mencione efectivo. Al pasar a gasto se retira el método exclusivo de ingreso y se elige un método válido del gasto.

Persistencia: catálogo opcional income_payment_methods dentro de la base cifrada del perfil, creado transaccionalmente al guardar el primer método. No usa almacenamiento global del navegador ni crea categorías financieras. Se conserva el valor custom:nombre en el campo de método existente; la validación solo lo admite para ingresos. Así se conserva el nombre en movimientos y programaciones aunque se restaure una copia sin catálogo. No se cambió el formato de movimientos, tablas contables ni la versión de la base: el catálogo es una extensión opcional que el cliente anterior puede ignorar y que viaja en el respaldo completo de SQLite. Las reglas de crédito, importes, balances y clasificación permanecen iguales.

En Aprende se quitó «Marcar como leído». El botón existente para continuar llama a la misma función de lectura antes de avanzar. Si falla, conserva la lección y su premio. La respuesta correcta sigue siendo necesaria para aprender y recibir el premio; no se cambian respuestas, contadores ni premios. Se conservan las imágenes, textos, fuegos artificiales y la eliminación de controles ya publicados.

Casos finales: catálogo persistido/idempotente, nombres inválidos, aislamiento por espacio, movimiento/edición, ingreso comercial/recurrente, reglas de crédito/tipo/importe, creación/selección/validación en UI y regresión de eliminación. Se ejecutó además el recorrido empaquetado de once consejos con variantes: sin botón separado, lectura antes de avanzar, fallo de lectura conserva la lección, premios/errores/reintentos, textos y animación.
