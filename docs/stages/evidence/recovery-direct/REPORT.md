# Direct password recovery and preserved legacy workspace

User reports two problems: the recovery link restarts email entry, and successful account reset then requires the forgotten local password. Read recent delivered recovery mail shapes only: the template uses /account/recovery with token_hash and type in the fragment, matching the supported format. Tokens were never logged, consumed in testing, or saved to evidence.

The legacy bridge now captures a one-use fragment in same-tab sessionStorage for at most10 minutes before clearing the bridge URL and forwarding to root. The account gate clears this transport before verification, handles later hashchange links even after initial ordinary entry, and shows explicit invalid/expired-link UI instead of silently requesting email again. Recovery asks only new password plus confirmation with visibility toggles. No second reset-mail request or password sign-in is performed automatically after updating Auth.

After verified password update, the app first opens the stable account key. If previous records cannot open, an existing device key can migrate them without asking the old password. Otherwise the user explicitly approved opening a fresh separate account workspace while preserving the old encrypted copy (async answer: Yes, preserve previous copy and allow a new space). This approval is the basis for the new-workspace fallback.

Each fallback selects a fresh IndexedDB namespace scoped by verified user UUID and random generation. The original database, encrypted sync/API/device metadata and biometric envelope remain in their original databases. No resetWebVault, deleteDatabase, archive-and-delete or financial API mutation is called. Account binding and stable key still enforce identity. An authenticated pointer is not assumed: the local pointer is just routing, is shape-validated, and the target ciphertext must still decrypt and match the verified account. Biometric namespaces follow the same generation, preserving earlier device envelopes. The pointer is committed after enrollment only. A visible banner says the old copy is preserved separately and those records were not recovered into the fresh workspace.
