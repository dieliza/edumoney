# Verified ordinary login across independent browsers

The previous repair handled reset completion, but ordinary sign-in still returned needsLegacy for another browser's unlinked vault. Safari's local state is independent of the browser used to reset/register the account, so its local recovery marker could not solve this. This is an account-entry flow defect, not evidence that the remote account needs to be recreated.

Every online ordinary login first verifies current credentials and confirmed user identity. It opens the stable account key when possible, transparently tries the current account password against older records, then an already configured device key. If no local key opens them, it uses the previously authorized separate account namespace, retaining the old copy intact and showing a notice. Owner mismatches also use a separate namespace rather than exposing another account's records; other storage failures still propagate. Subsequent sign-in reuses the enrolled namespace. No Auth password update/reset mail/account creation occurs as part of normal login.

Remove the legacy mode, its historical-password input, imports and needsLegacy transition from RequiredAccountGate entirely. Keep internal legacy support functions for compatibility, outside normal entry. Retain visibility controls, verification, recovery callbacks, loading locks, encrypted offline entry and trusted administrator identity. Existing namespace, encryption, biometric, financial, theme and calendar factories are preserved unchanged.

Verification completed before packaging:9 new service scenarios including two browser states, repeat login, transparent migration, invalid/unconfirmed credentials, other-account separation, storage failure and encrypted offline access;8 recovery service regression scenarios passed. TypeScript and targeted ESLint passed. Three final artifact UI scenarios planned. Physical Safari is unavailable; tests simulate independent browser storage rather than claiming a real device visit. No real account credentials were read/changed and no messages were sent.
